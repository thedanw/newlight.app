# Module Boilerplate

Generated by `.agents/planning/module-design/decision.md`. Copy this folder into
`src/modules/<id>/` and replace every `<Module>` / `<moduleId>` / `<kebab-id>`
with your module's values. The result is a valid module that:

- Mounts at `/<moduleId>` (no per-module layout; the shared `AppShell` owns chrome)
- Registers a settings section via `settings.ts`
- Routes lazily under `core/router.tsx`
- Imports UI only from the `@/core/ui` barrel

## File tree

```
src/modules/<id>/
├── manifest.ts            # typed contract (id, name, icon, number, basePath, nav)
├── public.ts              # public API surface (re-exports + ModuleApi type)
├── routes.tsx             # route children (no layout; no errorElement)
├── settings.ts            # registerSettingsSection({...}) at module load
├── index.tsx              # dashboard page (mounted at index route)
├── settings/              # module-local settings page (referenced by settings.ts)
│   └── <Module>SettingsPage.tsx
├── components/            # module-local UI building blocks
│   └── index.ts           # re-export barrel (add entries as components are built)
├── lib/                   # data layer: types, queries, hooks
│   ├── types.ts
│   ├── queries.ts
│   └── hooks.ts
└── pages/                 # non-dashboard pages
```

## Checklist after copying

- [ ] Edit `manifest.ts` — `id`, `name`, `icon`, `number`, `basePath`, `nav`.
- [ ] Edit `public.ts` — replace `<Module>` and `<moduleId>`.
- [ ] Edit `routes.tsx` — register your dashboard + page lazy imports.
- [ ] Edit `settings.ts` — `id`, `title`, `description`, `component`, `order`.
- [ ] Edit `settings/<Module>SettingsPage.tsx` — copy your section content here.
- [ ] Edit `index.tsx` — your dashboard UI.
- [ ] Edit `lib/types.ts` — derive from `Tables<'<your_table'>` (see `core/lib/database.types`).
- [ ] Add `lib/queries.ts` — Supabase calls return typed shapes.
- [ ] Add `lib/hooks.ts` — wrap queries in `useAsyncQuery` for `loading/error/data`.
- [ ] Update `src/core/router.tsx` to spread the module's routes under `AppShell`:
      `children: [ ..., { path: '<id>', children: <id>Routes } ]`
- [ ] Run `npm run typecheck` — must pass before commit.

## Rules (from `decision.md`)

- **No layout component per module.** `AppShell` is the only chrome.
- **No per-module `ErrorBoundary`.** `AppShell` provides one for every route.
- **No raw `style={{}}` or atomic `css()` outside rare shell recipes.** Use the
  `Page` slot recipe + `Card`/`Stack` from `@/core/ui`.
- **No direct `@ark-ui/*` imports** except `createListCollection` from
  `@ark-ui/react/collection` (and even then, prefer the barrel where possible).
- **No `styled-system/jsx` or `styled-system/css` outside this module's
  settings page hero block** (the one allowed exception for the module
  accent-shift). Everything else is `@/core/ui`.

## Public API contract

A module's public surface is `public.ts`. Other modules import from
`@/modules/<id>` — never from a file path inside the module. If you find
yourself reaching for a deep import, promote the value into `public.ts` first.
