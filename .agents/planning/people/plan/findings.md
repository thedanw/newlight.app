# Findings — Journey UUID Integrity Fixes

## Root cause
Migration `20260908200000_journey_stages_uuid_pk.sql` moved `journey_stages` PK slug→uuid and migrated `people.journey` values slug→UUID. Code written before the migration still assumes slugs or deterministic UUIDs:

1. `src/modules/people/pages/CreatePerson/Form.tsx:76` — defaults `journey` value to `'contact'` (slug); matches no `journey_stages.id`, so created people show no stage selected (`Journey.tsx:156,162` compare `currentStage === stage.id`)
2. `src/modules/people/lib/queries.ts:284-294` — delete-protection keys on 6 deterministic UUIDs that UI-created stages never have (dead code)
3. `supabase/functions/elvanto-sync-worker/people-sync.ts:229,364-368` — `resolveJourneyTrackId()` returns placeholder slug key `journey-track-sunday-services`; `loadJourneyTrackMap` (108-136) already loads the real UUID into `journeyTrackMap.sundayService` but it is never used
4. `supabase/functions/elvanto-sync-worker/transforms.ts:39-42` + `journey-sync.ts:285-292` — hardcode the 6 deterministic stage UUIDs ("must match migration seed values"); under UI-created stages these are orphan UUIDs
5. `supabase/functions/elvanto-sync-worker/people-sync.ts:11,703-705` — `DEFAULT_JOURNEY` hardcodes the contact stage UUID

## Seeds decision

Decided 2026-10-07: NO seed INSERTs for the 6 journey_stages. `JourneySettingsManager` (`src/modules/people/settings/JourneySettingsManager.tsx`) is the definitive mechanism for adding/deleting/managing stages and tracks; it creates rows with `crypto.randomUUID()` (`queries.ts:258,281`). Consequence: all code must resolve stage/track IDs at runtime (by slug), never assume deterministic UUIDs. The 6 canonical slugs (`contact|guest|linked|regular|archived|deleted_privacy_data`) remain semantic constants the sync worker depends on — protect them by slug, not id.

## Verification SQL

```sql
SELECT jt.name AS track, js.label AS stage
FROM people p, jsonb_each_text(p.journey) je(key, val)
LEFT JOIN journey_tracks jt ON jt.id = je.key::uuid
LEFT JOIN journey_stages js ON js.id = je.val::uuid
WHERE p.firstname = 'Rachel' AND p.lastname = 'Li';
```
