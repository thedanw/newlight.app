## Performance Optimizer Analysis (per `performance-optimizer` skill)

### Current Performance Characteristics

| Aspect | Implementation | Assessment |
|--------|----------------|------------|
| **Virtualization** | Optional windowing with `rowHeight`, `overscan` | ✅ Excellent for large datasets |
| **Selection State** | Controlled via `Set<string>`; stable `EMPTY_SELECTION` | ✅ No unnecessary re-renders from selection |
| **Row Rendering** | `useMemo` for rows array; `RowWrapper` per item | ⚠️ `RowWrapper` not memoized; re-renders on parent changes |
| **Toolbar Overlay** | Conditional render (`toolbarOpen && <overlay>`) | ✅ Good — avoids DOM when closed |
| **Document Listeners** | Single set at Root level (Task 9) | ✅ Fixed — was per-row before |
| **MassManage** | Conditional render (`selectedCount > 0`) | ✅ Good — Task 12 |
| **Transitions** | CSS `transition: all 0.4s ease` on multiple slots | ⚠️ `all` is broad; 400ms exceeds 300ms guideline |
| **Column Styles** | Shared utilities; applied via `cloneElement` | ⚠️ Dynamic prop spreading may prevent optimization |

### React Rendering Performance

#### Potential Re-render Triggers

| Component | Props That Change | Memoization | Risk |
|-----------|-------------------|-------------|------|
| `RootComponent` | `items`, `selectedKeys`, `openToolbarKey`, `scrollTop` | None | High — re-renders entire list on any change |
| `RowWrapper` | `selected`, `selectMode`, `open`, `onClick`, `select`, `button`, `toolbar` | None | High — new object refs each render |

1. **`RowWrapper` not memoized** — Receives new `select`, `button`, `toolbar` elements each render (created inline in `RootComponent`). Even with `React.memo`, the element refs change.

2. **Inline element creation in `RootComponent`** (lines ~200-250):
   ```tsx

   button={<RowButton icon={...} label="Manage" />}
   toolbar={renderRowToolbar?.(item, index, headers)}
   ```
   Creates new React elements every render → defeats `React.memo` on children.

3. **`useMemo` for `rows` array** — Good, but elements inside still new each time.

4. **Virtualization scroll handler** — `onScroll` on inner div updates `scrollTop` state → triggers Root re-render → re-renders all visible rows. Consider throttling or `requestAnimationFrame`.

5. **`Children.map` + `cloneElement` in `RowContent`** — Creates new elements; Panda may not extract static styles.

### Detailed: RowWrapper Memoization Strategy

**Current:**
```tsx
// In RootComponent - creates NEW elements every render
<RowWrapper
  select={<RowSelect checked={isSelected} onChange={...} />}
  button={<RowButton icon={...} label="Manage" />}
  toolbar={renderRowToolbar?.(item, index, headers)}
  ...
/>
```

**Optimized:**
```tsx
// 1. Stable callback refs via useCallback
const handleSelect = useCallback((key: string, checked: boolean) => {
  const newKeys = new Set(selectedKeys);
  checked ? newKeys.add(key) : newKeys.delete(key);
  handleSelectionChange(newKeys);
}, [selectedKeys, handleSelectionChange]);

const handleToolbarOpen = useCallback((key: string) => setOpenToolbarKey(key), []);
const handleToolbarClose = useCallback(() => setOpenToolbarKey(null), []);

// 2. Memoized RowWrapper
const RowWrapperMemo = React.memo(RowWrapper);

// 3. Pass stable props
<RowWrapperMemo
  key={key}
  item={item}
  index={index}
  selected={isSelected}
  selectMode={selectMode}
  onClick={onRowClick ? () => onRowClick(item, index) : undefined}
  onSelect={selectionEnabled ? () => handleSelect(key, true) : undefined}
  select={<RowSelect checked={isSelected} onChange={(c) => handleSelect(key, c)} />}
  button={<RowButton icon={...} label="Manage" onOpen={handleToolbarOpen} />}
  toolbar={renderRowToolbar?.(item, index, headers)}
  open={isToolbarOpen}
  onClose={handleToolbarClose}
/>
```

**But better:** Move `select`/`button`/`toolbar` creation INTO `RowWrapper` with props, so `RowWrapper` controls its own sub-components.
